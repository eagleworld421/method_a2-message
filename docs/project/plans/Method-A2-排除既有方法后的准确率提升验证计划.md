# Method-A2 排除既有方法后的准确率提升验证计划

> **文档状态：** 实验执行前计划，尚未执行本计划中的新实验。
>
> **适用范围：** Method-A2 S0 单一拓扑、完整观测、故障候选加正常候选。
>
> **权威定义：** [Method-A2-核心公式.md](../Method-A2-核心公式.md)。
>
> **实施上下文：** [Method-A2-Node-Marker-MVP执行方案与上下文同步.md](Method-A2-Node-Marker-MVP执行方案与上下文同步.md)。
>
> **历史依据：** 本计划在阅读 `method_a` 仓库的 Method-A1 实验报告与实现后制定，不重复已经完成且有结论的实验。

## 1. 目标、现状与边界

本计划的唯一性能目标是提升故障候选定位准确率，目标值为：

- Top-1 不低于 `0.60`；
- Top-3 不低于 `0.85`。

目标必须在未参与配置选择的测试集上报告。任何只在当前测试集上调参后得到的结果只能标记为探索性结果，不能作为正式达标结果。

当前 Method-A2 B 路径为 Node Marker：

\[
Z_m=E_\theta(X_m,G_m^{obs},M_m),
\]

\[
\widehat S^{CF}_{m,k}=D_\phi(Z_m,e_k,G_m^{obs},M_m),
\qquad e_k=(b_k,t_k).
\]

当前基线运行 `train-s0-marker-run1` 的结果为 Top-1 `0.09375`、Top-3 `0.34375`。在本工作区已进行的探索性调参中，`epochs=200`、`rank_temperature=0.05`、`lambda_list=5` 得到 Top-1 `0.34375`、Top-3 `0.59375`。该结果使用 32 个测试故障样本和单个随机种子，只能作为当前探索上界，不能作为正式性能结论。

本计划不保证目标一定可达。若真实反事实响应的 Oracle Top-K 已低于目标，必须停止模型改造，先修正数据生成或候选可分辨性问题。

## 2. 已排除的方法

以下方向已有 Method-A1 实验或实现证据，本计划不把它们作为新的主要方法，也不得在没有新问题定义的情况下重复运行：

- `ResidualRankingHead` 响应残差校正排序；
- 直接候选打分头和特权排序教师；
- 相对响应或候选差分监督；
- teacher、蒸馏和部署不可见物理条件输入；
- 仅通过增加事件数量的规模扩展；
- 仅通过扩大阻抗或工况模板覆盖的泛化实验；
- 仅扫描 `rank_temperature`、`lambda_list` 或训练轮数；
- 将 `global_repr`、QKV、可学习边打分或候选编号 embedding 重新加入 B 路径。

历史结论必须在开始执行前复核：

- A1 残差校正在 640 事件上约为 Top-1 `0.14583`、Top-3 `0.29167`；
- A1 直接候选打分约为 Top-1 `0.3021`、Top-3 `0.5729`；
- A1 相对响应监督在三个随机种子上使 Top-1 与 Top-3 均下降；
- A1 160、640、1600 事件规模实验显示样本增加有帮助但仍不能消除预测误差主导的排序瓶颈；
- A1 E0-COV 的高准确率覆盖臂包含评价上界或非部署条件，不能直接迁移为部署模型。

## 3. 新方案概览

本计划只验证四个尚未在当前 A2 MVP 中完成的新机制：

1. **鲁棒共享表示：** 从节点级编码中提取对单个事实故障节点不敏感的事件表示，降低真实故障位置污染；
2. **多尺度观测特征：** 同时利用故障初始传播和后续稳定响应，不增加候选差分监督；
3. **候选响应不确定性：** 为每个候选输出响应均值和方差，并以不确定性校正部署评分；
4. **主动困难候选仿真：** 根据验证集的错误候选对定向生成新的反事实事件，而不是无差别扩大数据量。

四个机制必须分阶段验证。不得一次性同时修改数据、编码器、解码器和损失，否则无法判断准确率变化来源。

## 5. 阶段零：数据可达性与 Oracle 门

### 5.1 目的

确定当前数据和新的事件参数空间是否具有达到 Top-1 `0.60`、Top-3 `0.85` 的真实物理可分辨性。

### 5.2 输入

使用当前 A2 数据目录中的：

- `X_obs.npy`；
- `signature_bank.npy`；
- `mask.npy`；
- `y_loc.npy`；
- `train_idx.npy`、`test_idx.npy`；
- `meta.json`；
- `feature_scaler.npz`。

### 5.3 计算

在当前 MVP 距离口径和核心公式规定的归一化距离口径下分别计算：

\[
d_{raw}(X,S_k)=\operatorname{mean}_{n,t,f}(X_{n,t,f}-S_{k,n,t,f})^2,
\]

\[
d_S(X,S_k)=
\frac{1}{|\Omega|}
\sum_{(n,t,f)\in\Omega}
\left(
\frac{X_{n,t,f}-S_{k,n,t,f}}{s_{n,f}}
\right)^2.
\]

只在故障候选集合上计算 Top-K，正常候选不得进入故障母线定位排名。必须额外报告：

- Oracle Top-1、Top-3；
- 真实候选平均名次；
- 每个事件的真实候选与最难错误候选间隔；
- 间隔小于预测误差预算的事件比例；
- 按节点、通道和拓扑距离分层的 Oracle 指标。

### 5.4 阶段门

- 若归一化 Oracle Top-3 小于 `0.85`，停止模型改造，进入数据可分辨性修正；
- 若归一化 Oracle Top-1 小于 `0.60`，不得宣称模型结构可以达到 Top-1 目标；
- 若 Oracle 达标但当前模型不达标，说明问题在特征提取、响应预测或部署评分，可以继续阶段一至四；
- Oracle 指标只能作为可达性上界，不得写入部署模型结果。

## 6. 阶段一：鲁棒共享表示

### 6.1 目标

减少事实观测中的真实故障位置对共享表示 (z_m) 的污染，同时保留节点级故障传播信息供候选解码器使用。

### 6.2 输入输出接口

编码器必须保持部署可见输入白名单：

```text
X_obs:       [B,N,T,F]
edge_index:  [E,2]
edge_attr:   [E,D_e]
edge_mask:   [B,E] or [E]
node_mask:   [B,N]
```

输出为：

```text
node_repr:   [B,N,D_h]
z_shared:    [B,D_z]
```

`z_shared` 不得读取真实位置、`group_id`、真实阻抗、真实反事实响应或训练期标签。

### 6.3 建议结构

先对每个节点进行时间编码和拓扑消息传递：

\[
h_{m,n}=E_{node}(X_{m,n},G_m^{obs},M_m).
\]

然后同时计算三类候选无关汇聚：

- 节点均值；
- 截尾均值；
- 节点中位数或 Huber pooling。

候选共享表示由这些统计量拼接后投影得到：

\[
z_m=E_{pool}
\left[
\operatorname{mean}(h_m),
\operatorname{trimmed\_mean}(h_m),
\operatorname{median}(h_m)
\right].
\]

节点级 `node_repr` 必须继续传入候选解码器，不能用 `z_shared` 替代所有节点信息。

首轮只比较以下三种池化，不增加注意力：

- `mean`：现有 MVP 对照；
- `trimmed_mean`：按节点维度去除最高和最低各 10%；
- `mean_median_concat`：均值与中位数拼接。

### 6.4 训练约束

不重新使用已经失败的候选差分监督。可保留已有合法 `L_pair`，但必须分别报告：

- `z_shared` 的同组距离；
- `node_repr` 的同组距离；
- 真实故障位置 probe 的准确率；
- 事件参数 probe 的 R²。

若 `z_shared` 的故障位置 probe 仍明显高于随机基线，说明鲁棒池化没有达到设计目标。

### 6.5 验收

每种池化必须在同一训练、验证和测试划分上报告：

- `L_family`；
- Top-1、Top-3；
- 平均名次；
- 真实候选 signed margin；
- `z_shared` 的故障位置 probe；
- 参数量和前向耗时。

只有验证集 Top-1 或 Top-3 在至少两个随机种子上改善，才进入阶段二。

## 7. 阶段二：多尺度观测特征

### 7.1 目标

补充当前六个原始电压通道中未显式表达的传播变化，增强候选响应的时间辨识度。

### 7.2 特征构造

从原始六通道构造部署时可计算的派生通道：

\[
[\Re V,\Im V,|V|,\angle V,\Delta_t|V|,\Delta_t\angle V].
\]

相位差必须使用连续相位展开，不能直接对 ([-π,π]) 的相位值做普通差分。所有标准化统计量只能来自训练集。

### 7.3 双时间尺度编码

使用两个并行 TCN 分支：

- 短窗口分支：较小卷积核，提取故障初始传播；
- 长窗口分支：较大感受野，提取后续稳定响应。

两个分支在节点级拼接后进入现有拓扑编码器。候选集合、`e_k`、输出形状和正常候选语义保持不变。

### 7.4 对照

至少执行以下四臂：

- 原始六通道 + 单尺度 TCN；
- 派生通道 + 单尺度 TCN；
- 原始六通道 + 双尺度 TCN；
- 派生通道 + 双尺度 TCN。

不得同时改变池化方式、排序损失和数据集，否则无法归因。

### 7.5 验收

派生特征只有在验证集上同时改善 Top-1 或 Top-3，并且没有造成 Oracle 口径变化异常、数值溢出或节点置换测试失败时才保留。

## 8. 阶段三：候选响应不确定性

### 8.1 目标

处理不同候选的响应预测误差方差不同的问题，避免某个候选因为预测不稳定而被错误地排到前面。

### 8.2 输出接口

解码器对每个候选输出：

```text
response_mean: [B,C,N,T,F]
response_logvar: [B,C,N,T,F]
```

`response_mean` 必须与现有 `response` 语义一致。`response_logvar` 只表示模型预测不确定性，不可读取真实候选评分或真实位置。

### 8.3 损失

使用训练集尺度归一化的异方差高斯损失：

\[
L_{unc}=
\frac{1}{|\Omega|}
\sum_{n,t,f}
\left[
\frac{(S_{n,t,f}-\mu_{n,t,f})^2}
{2\sigma^2_{n,t,f}}
 + \frac{1}{2}\log\sigma^2_{n,t,f}
\right].
\]

方差必须限制在有限范围内，例如通过 `logvar.clamp(-8, 8)`，并记录是否触发截断。

部署候选评分定义为：

\[
R_{m,k}^{unc}
=
\frac{d_S(X_m,\mu_{m,k})}
{\operatorname{mean}_{n,t,f}(\sigma^2_{m,k,n,t,f})+\epsilon}.
\]

同时保留原始 (d_S) 作为对照，不得只报告不确定性分数。

### 8.4 验收

必须报告：

- 原始 (d_S) 的 Top-1、Top-3；
- 不确定性评分的 Top-1、Top-3；
- 平均名次和 hardest-negative 命中率；
- 方差与真实绝对响应误差的校准相关性；
- 方差截断比例。

若不确定性评分在验证集没有稳定改善，停止该分支，不将其用于最终测试。

## 9. 阶段四：主动困难候选仿真

### 9.1 目标

针对当前模型最容易混淆的候选对生成新数据，避免重复 Method-A1 的无差别样本扩充实验。

### 9.2 困难候选对定义

在验证集上对每个故障事件记录：

- 真实候选 (k^{true})；
- 当前预测第一名 (k^{pred})；
- 当前预测前三名中的错误候选；
- 真实响应距离最小的错误候选；
- 候选间真实 (d_S) 间隔；
- 模型预测间隔。

优先级按以下顺序排序：

1. 当前 Top-1 错误且真实间隔小；
2. 当前 Top-3 错误且真实间隔小；
3. 同一候选对在多个事件中重复混淆；
4. 相同拓扑距离和相同局部结构的候选对。

### 9.3 新数据生成

对于每个困难候选对，在不改变拓扑的条件下重新采样：

- 负荷倍率；
- 故障阻抗；
- 故障时刻；
- 事件随机状态。

同一反事实族内所有候选必须共享这些参数，候选相关随机扰动必须保持关闭或共享。新数据必须保存：

- `group_id`；
- 事件参数摘要；
- 真实位置；
- 真实候选响应；
- 生成种子；
- 来源困难候选对。

困难数据只能加入训练集或开发集，不能加入最终测试集。最终测试集必须在主动采样策略冻结后重新生成或冻结索引。

### 9.4 验收

主动数据必须证明：

- 困难候选对在训练前确实是高错误率或小物理间隔；
- 训练后对应候选对的验证错误率下降；
- 非困难候选的 Top-K 不明显退化；
- 训练集与验证集的 `group_id` 不重叠；
- 没有把真实位置、预测标签或测试数据写入部署前向输入。

## 10. 训练与评价协议

### 10.1 数据划分

按共享事件 `group_id` 划分：

- 训练集：70%；
- 验证集：15%；
- 测试集：15%。

同一 `group_id` 的不同事实故障位置不得跨集合。正常候选样本不参与故障 Top-K，但可以参与响应族重构。

### 10.2 随机种子

每个候选方案至少运行 `342`、`343`、`344` 三个种子。只有三个种子都完成，才能计算均值和标准差。

### 10.3 模型选择

只使用验证集选择：

- pooling 类型；
- 多尺度特征开关；
- 不确定性分支开关；
- 损失权重；
- 最佳 epoch。

测试集只能在配置冻结后运行一次。

### 10.4 必须报告的指标

- Top-1；
- Top-3；
- Top-5；
- 真实候选平均名次和中位名次；
- signed margin；
- hardest-negative 一致率；
- Oracle Top-K；
- `L_family`、`L_pair`、新增损失；
- 预测误差与真实候选间隔之比；
- 参数量、训练时间和单批次前向时间。

## 12. 反捷径与信息边界测试

每个新模型必须通过以下测试：

- 候选轴置换等变；
- 节点同步置换等变；
- 预测时不读取真实位置；
- 预测时不读取 `group_id`；
- 预测时不读取真实反事实响应；
- `z_shared` 不因候选顺序变化而变化；
- 随机替换候选标记后输出只发生相应候选变化；
- 方差输出为有限值；
- 全零或部分节点掩码不会产生 NaN；
- 训练集统计量不会读取验证集或测试集。

如果加入主动困难候选数据，还必须审计困难候选来源不会把测试集预测结果或测试标签写入训练数据。

- 训练、验证和测试数据契约通过；
- 没有信息泄漏；
- 至少两个种子完成；
- 验证集指标没有明显退化。

### 13.2 达标判定

正式达标必须同时满足：

- 三个随机种子测试 Top-1 均不低于 `0.60`，或者均值不低于 `0.60` 且 95% 置信区间下界不低于预注册门槛；
- 三个随机种子测试 Top-3 均不低于 `0.85`，或者均值不低于 `0.85` 且 95% 置信区间下界不低于预注册门槛；
- Oracle Top-K 高于对应目标；
- 测试集没有参与配置选择；
- 所有信息边界测试通过。

如果只达到其中一个目标，必须分别报告，不得用 Top-3 达标掩盖 Top-1 失败，反之亦然。

### 13.3 失败判定

出现以下任一情况必须停止扩展模型并报告：

- Oracle Top-K 低于目标；
- 新结构只改善训练集而验证集退化；
- 主动困难数据导致训练—验证泄漏；
- 新增不确定性分支产生无限值或异常方差；
- 多个随机种子方向相反且差异超过单个样本的统计波动；
- 需要修改核心公式才能继续，但用户尚未批准。

## 14. 执行 Agent 的最终报告要求

执行完成后必须回答：

1. 哪个阶段通过，哪个阶段失败；
2. 当前使用的模型、数据和损失配置；
3. 验证集与测试集的 Top-1、Top-3 和平均名次；
4. Oracle Top-K 是否支持目标；
5. 鲁棒池化是否降低了共享表示中的故障位置信息；
6. 多尺度特征是否改善了候选间隔；
7. 不确定性评分是否改善了排序；
8. 主动困难候选数据是否降低了对应错误率；
9. 三个随机种子之间的均值、标准差和置信区间；
10. 所有数据、日志、配置、指标和报告的绝对路径；
11. 是否存在任何未执行、失败、泄漏或不可外推内容。

执行 Agent 不得把单个种子、测试集调参结果、Oracle 上界或非部署覆盖臂结果写成正式模型准确率。
