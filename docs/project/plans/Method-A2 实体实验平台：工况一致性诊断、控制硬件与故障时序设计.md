## 1. 目标与设计边界

Method-A2
需要在实体配电网络中，针对同一事件条件生成不同故障位置下的反事实响应，并采集各节点三相电压数据。实验平台不仅要复现网络拓扑，还要能够重复地切换故障位置、注入规定故障、同步采集响应，并判断每次实验是否满足工况一致性要求。

当前已确定或沿用的约束：

1.  采用 IEEE 13 配电网作为实体网络的主要拓扑参考。
2.  使用固定 RLC 负荷；当前 A2
    不开展故障距离变化，因此不需要通过改变负荷来模拟距离变化。
3.  故障注入范围遵循现有 Method-A2 场景
    S0--S4。**不增加断路/断线故障场景。**
4.  同一反事实事件内，真实网络、运行条件和故障条件保持一致，只改变候选故障位置。
5.  采集目标是多节点三相电压响应，并进一步形成 A2
    所需的复电压表示，而不是仅测量零序电流。
6.  保护系统必须独立、可靠。不得为了获得完整故障数据而绕过或禁用安全保护。

本文讨论的工况诊断器，不是故障定位模型，也不是用于补偿故障后电压跌落的闭环稳压器。它的职责是：**确认实验是否具备开始条件、记录故障实际发生时序、判断采集数据是否有效，并在异常时安全终止实验。**

## 2. Method-A2 反事实实验中的一致性要求

沿用当前项目已确认的物理定义：

\[ X_m=`\psi`{=tex}(G_m^{true},H_m,C_m,K_m^{true}) \]

\[ S\^{CF}\_{m,k}=
`\psi`{=tex}(G_m\^{true},H_m,C_m,`\operatorname{do}`{=tex}(K_m=k)) \]

\[
`\mathcal{S}`{=tex}\^{CF}*m={S\^{CF}*{m,k}}\_{k`\in`{=tex}`\mathcal{K}`{=tex}\_m}
\]

在同一事件的候选响应生成过程中，实验设计要尽可能保持共同物理条件不变，只切换故障位置
(k)。这里不重新定义项目中的 (H_m)、(C_m)、(K_m) 或 (S\^{CF})。

因此，硬件与软件系统需要分别保证：

-   **配置一致性：**
    电源、真实网络拓扑、线路参数、固定负荷、接地方式、故障类型/相别/阻抗、测量链路等配置不发生非预期变化。
-   **故障前状态一致性：** 每次注入前，网络恢复到可比较的稳态初始条件。
-   **时间一致性：**
    故障实际建立时刻、触发相角、采样时钟和响应窗口具有可追溯、可比较的时间基准。
-   **数据有效性：**
    保护动作、限流、采集饱和、丢样或同步异常等情况被记录并正确标记。

必须区分：**参数相同不等于故障后的响应相同。**
不同故障位置导致不同等效阻抗，因而故障电流、节点电压和负荷实际功率可以不同。这些变化是需要观测的物理结果，不应由控制器强行调成一致。

## 3. 工况诊断器需要检查的变量

### 3.1 三相电源

  -----------------------------------------------------------------------------------------------------------------
  变量                     一致性要求                           原因与检查方式
  ------------------------ ------------------------------------ ---------------------------------------------------
  三相电压有效值           每轮实验保持在设定容差内             电源幅值变化会改变全网电压和故障响应；故障前测量
                                                                RMS

  频率                     保持稳定                             频率影响线路电感、电容的电抗；通过电压波形估计

  相序及相间相角           保持一致                             相序错误或相角偏差会改变三相运行状态

  电源波形失真             保持在标定范围内                     谐波会影响响应及相量提取

  电源等效输出阻抗         设计和校准时确定，实验期间不应改变   影响故障电流和电压跌落；不能只看空载/正常运行电压

  电源控制模式及限流设置   固定并记录                           限流、折返或关断会改变故障期间的物理响应

  电源保护状态             每轮记录                             判断是否发生非预期保护或限流
  -----------------------------------------------------------------------------------------------------------------

电源选择不能只看额定
VA。还需要验证其短路期间的限流特性、输出阻抗、故障持续能力和保护行为是否与目标物理模型相容。可编程交流源有利于设置电压、频率和相位，但不意味着实验中应通过动态调压来抵消故障造成的压降。

### 3.2 真实线路网络与拓扑

  变量                       一致性要求             原因
  -------------------------- ---------------------- ------------------------------------
  真实网络拓扑 (G\^{true})   固定                   拓扑决定各节点间电气路径
  各段线路 R、L、C           固定并经过标定         决定线路阻抗和故障响应
  相别配置                   固定                   单相、两相和三相线路的电气行为不同
  线路互耦参数               按设计固定并纳入模型   会影响不对称故障下的相间响应
  支路开关状态               每轮确认               开关状态改变会改变真实拓扑
  变压器参数及分接头         固定并记录             影响电压变换和故障电流
  中性点、接地和回流路径     固定                   对接地故障和零序响应尤其重要
  并联电容器状态             固定                   影响网络导纳和电压响应

实验平台应区分真实物理拓扑 (G\^{true}) 与模型可能使用的观测拓扑
(G\^{obs})。例如，某些实验可以改变模型可见的拓扑信息，但同一组反事实物理响应采集期间，真实网络不能因而发生非预期变化。

### 3.3 固定负荷

当前采用固定阻抗负荷，因此每轮不需要主动调节负荷功率。应保持：

-   各节点 R、L、C 元件参数；
-   每相负荷的接入位置和相别；
-   Y/Δ 接线方式；
-   负荷开关状态；
-   负荷元件温度处于校准容差范围内。

固定阻抗不意味着实际负荷功率固定。例如，电阻负荷
(R=20,`\Omega`{=tex})，端电压从 10 V 降至 8 V 时，功率由
(5`\text{ W}`{=tex}) 降至
(3.2`\text{ W}`{=tex})。这种故障造成的功率变化是正常响应，不需要控制器补偿。

IEEE 13 的相别和连接方式必须保留。1F、2F、3F 表示单相、两相、三相；Y
表示星形连接，D/Δ
表示三角形连接。单相线间负荷与单相相线---中性线负荷不能混为一谈。

### 3.4 故障注入条件

同一事件的不同候选位置实验中，应保持以下故障条件一致：

-   故障类型；
-   故障相别或相组合；
-   故障阻抗及其实际标定值；
-   故障注入模块和连接导线的寄生阻抗；
-   故障触发相角（当研究窗口包含对暂态敏感的部分时）；
-   故障持续时间和切除协议；
-   故障注入开关的动作方式及反馈定义。

唯一主动改变的是故障接入位置。故障阻抗应尽量在各候选位置保持一致；不能只保证阻抗档位相同，却忽略不同位置开关、导线和连接器带来的额外串联阻抗。

### 3.5 温度与初始储能状态

线路、负荷和故障阻抗模块的温升可能改变元件参数。每轮实验前应检查关键器件温度，并按需要等待冷却或重新校准。

电感电流和电容电压等初始储能状态也会影响暂态响应。每轮故障前应先恢复正常网络状态，等待达到规定的稳态条件；不能仅凭"上一轮故障已经切除"就认为初始状态相同。

### 3.6 测量系统

应保持测量链路配置一致：

-   传感器及调理电路的增益、偏置和校准版本；
-   DAQ 采样率、量程、滤波和触发配置；
-   多通道共用采样时钟或经过验证的同步机制；
-   电压相量的统一参考相位；
-   通道---节点---相别映射；
-   数据窗口、相量计算和预处理版本。

A2
使用三相复电压的实部和虚部。相位参考不统一，即使物理波形接近，也可能产生不同的
Re/Im 数值。因此，统一相位参考和同步采样是必要条件。

## 4. 不应强制保持一致的故障后变量

以下量是故障位置变化后自然产生的响应，不应被工况控制器强制调成相同：

-   各节点故障后电压；
-   各支路故障电流；
-   故障点电压和故障电流；
-   固定阻抗负荷的实际功率；
-   故障传播或暂态响应的空间分布。

简化地看：

\[ I_f(k)`\approx`{=tex} `\frac{V_{\mathrm{th}}(k)}`{=tex}
{Z\_{`\mathrm{th}`{=tex}}(k)+Z_f} \]

不同位置的 (Z\_{`\mathrm{th}`{=tex}}(k))
可以不同，因此不同位置的故障电流不同并不意味着工况不一致。

控制器也不应通过改变电源电压或故障阻抗来强行使各位置故障电流相等，否则会破坏"只改变故障位置"的实验设计。

## 5. 工况诊断器的硬件架构

建议采用四个相互分工的部分：

1.  **上位机（Python）：**
    生成实验计划、配置设备、执行工况判定、保存数据和生成质量报告。
2.  **实时控制器（MCU）：**
    执行故障位置选择、开关互锁、相位同步触发、状态反馈记录和 DAQ
    事件标记。
3.  **同步数据采集系统（DAQ）：**
    采集各节点三相电压、关键支路/电源电流，以及触发和保护状态信号。
4.  **独立硬件保护：** 承担过流、过温、急停和安全切断。保护不能依赖
    Python、USB/串口通信或普通软件状态机。

总体结构：

``` text
                  Python 上位机
       实验配置 / 工况验收 / 数据处理 / 保存
                  │             │
                  ▼             ▼
             MCU 实时控制器   同步 DAQ
          开关/相位/互锁/触发  多通道波形采集
                  │             ▲
                  └──────┬──────┘
                         │
                实体 IEEE 13 网络
       三相电源—线路模块—固定负荷—故障注入模块

       独立硬件保护：过流 / 过温 / 急停 / 切断
       （独立于上位机软件，保护动作优先）
```

### 5.1 电源

建议选择具有隔离输出、三相交流输出和可配置电压/频率的可编程交流源，或经过论证的隔离式三相电源方案。采购前必须核实：

-   电压、频率及相角设置能力；
-   额定容量和短时输出能力；
-   输出阻抗及其可标定性；
-   故障期间限流、折返和关断行为；
-   保护动作和状态读取接口。

此前讨论过 Chroma 61700
系列作为可编程三相交流源的功能参考，但其具体型号、容量和适用性尚未定型，不能直接视为采购结论。

### 5.2 MCU 实时控制器

可用 STM32G4 系列开发板（例如
NUCLEO-G474RE）作为原型控制器。其职责包括：

-   控制候选故障位置和故障模块；
-   执行开关互锁；
-   读取隔离后的电源相位参考；
-   使用硬件定时器执行触发；
-   读取开关辅助触点和保护状态；
-   向 DAQ 输出硬件事件标记；
-   记录命令时间、反馈时间和动作状态。

STM32 型号只是原型候选，最终选型取决于 I/O
数量、隔离接口、定时器资源、通信方式和抗干扰设计。

机械继电器存在动作延迟和触点抖动，MCU
发出命令的时刻不等于实际触点闭合时刻。如果暂态采集对触发相角敏感，必须测量实际动作反馈；必要时评估适合交流故障注入的固态开关，但要把漏电流、导通压降、关断特性和故障电流承受能力纳入校准。

### 5.3 同步 DAQ

采集系统应优先满足：

-   足够的电压通道数；
-   同步采样，而非仅仅多个通道都能采样；
-   适当的采样率、分辨率和输入量程；
-   低噪声、低通道间相位误差；
-   外部触发或事件标记输入；
-   可与 MCU 共享时钟或进行可靠同步；
-   能够连续记录故障前、故障中和故障后的原始波形。

如果有 (N) 个需要测量的节点，理论三相电压通道上限为
(3N)，但实际通道数应按各节点真实存在的相别确定，不能为不存在的相别虚设通道。

此前讨论的 NI CompactDAQ 可作为研究级同步采集架构参考。某些 16
通道同步模块可以组合扩展通道数，但采购时必须逐项核实模块兼容性、同步方式、输入范围、采样率、实际噪声和可用状态。不能仅凭"16
bit"或"24 bit"标称分辨率判断是否满足 A2。

例如，若采集输入范围为 ±10
V，而待测相电压峰值超过该范围，则需要设计经过校准的电压缩放和输入保护。差分输入不自动等于通道间电气隔离，必须检查共模电压、接地和隔离要求。

### 5.4 信号调理与传感器

参考 Tang
论文中的传感器和运放调理思路，但不能直接照搬其主要面向馈线电流/零序电流测量的方案。A2
的主要采集对象是多节点三相电压。

前端需要按实际电压范围设计差分测量、隔离、比例变换、偏置（如 ADC
需要）和抗混叠滤波。所有通道应经过增益、偏置、相位和温漂校准。电流传感器用于监测电源输出和关键支路，辅助判断故障建立及保护状态。

## 6. 软件架构与职责

建议使用 Python 作为上位机，不必为第一版引入复杂控制软件平台。

  ----------------------------------------------------------------------------------
  软件功能                候选工具                职责
  ----------------------- ----------------------- ----------------------------------
  仪器通信                PyVISA                  配置和读取支持 SCPI 的电源/仪器

  MCU 通信                PySerial 或等效接口     下发实验计划、读取控制器反馈

  DAQ 控制                NI-DAQmx Python API     配置同步采样、触发和数据读取
                          或设备厂商 SDK          

  信号处理                NumPy、SciPy            RMS、频率、相量、滤波和质量检查

  数据管理                HDF5、JSON、NumPy       保存原始波形、配置和质量报告

  实验管理                Python 状态机           管理实验顺序、异常处理和候选切换
  ----------------------------------------------------------------------------------

### 6.1 软件模块

-   `experiment_config`：实验编号、候选位置、故障类型/相别/阻抗、采样和触发参数。
-   `device_manager`：电源、MCU、DAQ 和传感器状态。
-   `condition_validator`：配置一致性和故障前稳态检查。
-   `fault_controller`：向 MCU 下发受控故障计划；不直接依赖 Windows
    软件延时决定精确触发。
-   `acquisition_manager`：启动预触发采集、记录硬件事件和读取波形。
-   `safety_monitor`：读取保护状态；真正的切断由独立硬件完成。
-   `response_processor`：从原始波形提取 A2 所需的三相复电压时间序列。
-   `data_manager`：保存原始数据、派生响应和实验元数据。

### 6.2 工况检查的判定内容

  检查对象            软件检查方式                       未通过时的处理
  ------------------- ---------------------------------- --------------------
  电源 RMS 电压       与基准值比较                       等待恢复或禁止注入
  电源频率            估计频率并比较                     禁止注入
  相序、相间相角      相序和角度检查                     禁止注入
  节点故障前电压      有效相别的幅值/相角比较            等待稳定或排查
  关键支路电流        与基准状态比较                     排查负荷或接线
  拓扑开关状态        读取实际辅助触点                   禁止注入
  固定负荷/故障模块   配置版本、温度和状态检查           排查或等待冷却
  故障阻抗            档位反馈、标定状态                 禁止注入
  DAQ 状态            通道、时钟、触发、饱和和丢样检查   禁止采集
  保护状态            就绪信号和历史动作记录             禁止注入

线路 RLC
和固定负荷参数不必每轮在线测量，可在装配、维护和周期校准时测量；每轮结合配置版本、开关状态、温度和故障前电气状态进行检查。

### 6.3 故障前电气状态比较

可用基准稳态下的节点电压相量作为每轮准入检查的一部分。对参考幅值有效的节点和相别，计算：

\[ e_V=`\max`{=tex}*{n,`\phi`{=tex}}
`\frac{\left||V_{n,\phi}^{pre}|-|V_{n,\phi}^{ref}|\right|}`{=tex}
{\|V*{n,`\phi`{=tex}}\^{ref}\|} \]

以及相角偏差：

\[ e\_`\theta`{=tex}=`\max`{=tex}*{n,`\phi`{=tex}} `\left`{=tex}\|
`\operatorname{wrap}`{=tex} `\left`{=tex}(
`\angle `{=tex}V*{n,`\phi`{=tex}}\^{pre}
-`\angle `{=tex}V\_{n,`\phi`{=tex}}\^{ref} `\right`{=tex})
`\right`{=tex}\| \]

只对真实存在且可观测的相别计算。具体容差不能现在凭经验直接定成某个百分比，应通过无故障重复实验、仪器不确定度和候选响应差异共同确定。

相同的故障前电压并不能证明所有隐藏物理参数都相同，因此该检查必须与电源输出阻抗标定、线路/负荷配置管理和温度监测结合。

## 7. 故障时序与"错误时间切断"的风险

### 7.1 必须区分两个问题

**故障位置诊断**：比较不同候选响应与观测响应，判断哪个位置最可能。候选响应接近会导致定位误判。

**故障注入与切断控制**：决定何时接入故障、采集多久、何时切除。它应依据预设实验计划、硬件时序和实际开关反馈，而不是依据故障位置诊断结果。

因此，候选响应接近本身不会必然导致错误切断。只有当控制器依赖电压/电流响应阈值来判断故障时段或切断时刻时，才会把响应可辨识性问题引入控制逻辑。

### 7.2 不推荐的方式

不建议使用"检测到电压跌落后开始计时"或"检测到电流超过阈值后决定正常切断时间"作为唯一的实验时序控制方法。高阻故障可能响应较弱，噪声、暂态和测量误差也可能造成误触发或延迟触发。

电气量可以用于故障建立确认、数据对齐和异常监测，但不应成为唯一的正常切断时序来源，更不能代替独立安全保护。

### 7.3 推荐方式：预设时序 + 实际反馈 + 独立保护

记录并区分以下时间：

-   (t\_{cmd})：MCU 发出故障开关命令的时间；
-   (t\_{contact})：辅助触点反馈确认开关动作的时间；
-   (t\_{fault})：根据开关反馈和同步电气波形估计的实际故障建立时间；
-   (t\_{planned})：实验计划的正常切断时刻；
-   (t\_{protect})：独立保护实际动作时刻；
-   (t\_{hardlimit})：独立硬件安全时限。

计划切断时间可以基于确认的故障建立参考设置：

\[ t\_{planned}=t\_{on}+`\Delta `{=tex}t\_{test} \]

其中 (t\_{on})
应在系统设计时明确采用哪个经过验证的实际事件参考，而不能默认等于上位机命令时间。

正常实验中，计划切断与独立保护共同决定最终切断：任何保护动作或硬件安全截止都应优先于计划采集时长。若保护未动作，可将其事件时间视为不参与本轮取最小值。还要考虑开关实际断开延迟，并记录实际电气故障消失时刻。

安全保护不能为了完整采样而被延迟、屏蔽或绕过。若保护在目标采集窗口内动作，应记录保护原因和时间，并判断该数据是否仍符合目标物理响应定义。

### 7.4 时间对齐问题

\[ t\_{command}`\ne `{=tex}t\_{contact}`\ne `{=tex}t\_{stable fault} \]

机械继电器存在动作延迟和触点抖动。即使 MCU
知道命令发出时间，也不代表电气故障已在该时刻稳定建立。

建议：

1.  DAQ 在故障注入前就开始预触发记录。
2.  MCU 的硬件事件标记同时送入 DAQ。
3.  记录实际开关辅助触点反馈。
4.  同步采集电压和关键电流，辅助估计电气故障建立时刻。
5.  对 S4 等响应较弱的故障，不依赖单一固定电流阈值确认故障。
6.  对故障建立时刻无法可靠确定、触点严重抖动或波形缺失的样本，标记为时间不确定或无效，不应静默地用命令时间替代。

## 8. 推荐的软件状态机

``` text
IDLE
  ↓
CONFIGURE       配置电源、故障类型、阻抗和位置
  ↓
SETTLE          恢复正常网络状态并等待稳态
  ↓
VERIFY          检查配置、故障前状态和保护就绪
  ├── FAIL → 等待恢复 / 人工排查 / 终止
  ↓ PASS
ARM_DAQ         启动同步采集和预触发缓冲
  ↓
INJECT          MCU 按预设相位/时序执行故障注入
  ↓
ACQUIRE         采集故障响应及开关、保护状态
  ↓
RECOVER         按安全程序切除故障并恢复网络
  ↓
VALIDATE        检查时间、通道、保护动作和数据完整性
  ├── FAIL → 保存失败记录，不自动进行不安全重试
  ↓ PASS
SAVE            保存原始波形、派生响应和元数据
  ↓
NEXT_CANDIDATE  切换下一个故障位置
  ↓
SETTLE
```

任意阶段出现急停、过流、过温或其他安全故障时，独立硬件保护优先动作；软件随后进入故障锁定状态。状态机不能覆盖或屏蔽保护动作。

## 9. 数据保存方案

建议分为原始实验层和模型数据层。

### 9.1 原始实验层

``` text
experiment_m/
    config.json
    baseline_waveform.h5
    candidate_k1/
        trial_1.h5
        trial_2.h5
        trial_3.h5
    candidate_k2/
        trial_1.h5
        trial_2.h5
        trial_3.h5
    quality_report.json
```

每个原始文件建议包含：

-   全部实际采集通道的原始波形；
-   采样率、量程、时钟和触发配置；
-   电源设定及实测状态；
-   真实拓扑和负荷配置版本；
-   故障类型、相别、阻抗档位和候选位置；
-   命令、开关反馈、故障建立估计和切断时间；
-   温度、保护状态和保护动作时间；
-   丢样、饱和、同步异常和质量标记；
-   传感器/调理电路校准版本；
-   软件版本和实验配置版本。

### 9.2 模型数据层

从原始波形按统一处理流程提取：

\[ S\^{CF}\_{m,k} \]

并形成项目当前要求的三相复电压实部、虚部时间序列。节点相别缺失时应使用明确的掩码，而不是把不存在的相别当作有效测量值。

必须保留原始波形。这样在后续发现相位参考、触发时间、滤波或相量计算策略存在问题时，可以重新处理，而不必重新注入故障。

真实故障位置、故障阻抗和其他隐藏物理条件可以保存在实验元数据中用于监督和审计，但不能意外泄漏到模型部署时不允许访问的输入中。

## 10. 重复性与数据质量验收

同一候选位置、相同配置下重复采集：

\[ S\^{CF,(1)}*{m,k},`\quad `{=tex}S\^{CF,(2)}*{m,k} \]

定义重复误差：

\[ E\_{`\mathrm{repeat}`{=tex}}=
d_S`\left`{=tex}(S\^{CF,(1)}*{m,k},S\^{CF,(2)}*{m,k}`\right`{=tex}) \]

不同候选位置间的响应差异：

\[ `\Delta`{=tex}*{k,j}=
d_S`\left`{=tex}(S\^{CF}*{m,k},S\^{CF}\_{m,j}`\right`{=tex}) \]

重点检查最难区分的候选是否满足：

\[ E\_{`\mathrm{repeat}`{=tex}}`\ll`{=tex}`\Delta`{=tex}\_{k,j} \]

这是一项实验质量目标，不是无条件保证。重复误差还包含传感器噪声、触发偏差和器件随机变化。若某些候选的真实物理响应本来就非常接近，控制器不能通过人为改变工况来放大候选差异。

建议将质量结果拆成两个标志：

-   `precondition_pass`：故障前配置和运行状态是否符合准入条件；
-   `response_quality_pass`：故障建立时序、采集完整性、保护行为和测量质量是否满足数据使用要求。

"故障前工况通过"不等于"本次响应数据一定有效"；两者应分别报告。

## 11. 第一版原型实施顺序

不建议一开始就完成全部 IEEE 13
节点和所有故障类型。先验证工况控制、同步采集和安全时序，再扩展网络规模。

### 阶段 A：控制与采集链路验证

-   小规模隔离低压三相网络；
-   两个可切换故障位置；
-   一种经过安全评估的 A2 范围内故障；
-   固定 RLC 负荷；
-   MCU 控制、DAQ 同步记录；
-   完成故障前状态检查、实际开关反馈、保护记录和原始数据保存。

### 阶段 B：重复性验证

-   相同位置和相同条件重复采集；
-   交替切换两个候选位置；
-   估计故障前状态波动、故障触发时间偏差和响应重复误差；
-   检查候选间物理差异是否大于实验重复误差；
-   检查保护动作是否改变目标采集窗口。

### 阶段 C：网络扩展

-   按 IEEE 13 的真实相别、串并联拓扑、接地和负荷连接方式扩展线路；
-   按标幺物理等效原则确定线路、电源、负荷和故障参数；
-   增加 A2 需要的故障位置及 S0--S4 对应故障配置；
-   扩展同步电压通道和必要的电流/状态通道；
-   重新执行整个平台的重复性和安全验收。

## 12. 当前建议与尚未确定事项

### 12.1 当前建议

1.  **总体架构：** Python 上位机 + MCU 实时控制器 + 同步 DAQ +
    独立硬件保护。
2.  **负荷：** 固定 RLC，不增加动态负荷功率控制。
3.  **故障时序：** 预设实验时序，使用实际开关反馈和 DAQ
    事件标记校准时间；不让故障定位结果决定切断时刻。
4.  **安全：** 保护独立于软件，保护动作优先于实验计划。
5.  **采集：** 重点投入多节点三相电压的同步采集、前端调理和相位校准。
6.  **数据：** 原始波形与派生 A2 响应同时保存。
7.  **验收：**
    同时评估故障前工况一致性、故障时序重复性和候选响应可区分性。

### 12.2 尚未确定，需要后续计算或实验决定

-   实验平台额定相电压、线电压和功率等级；
-   电源具体型号、容量、输出阻抗和故障期间限流行为；
-   各节点实际需要采集的相别及总通道数；
-   DAQ 型号、采样率、分辨率、噪声、通道同步误差和输入范围；
-   电压/电流传感器及调理电路的具体方案；
-   故障开关类型、动作延迟、触点抖动和故障电流承受能力；
-   各故障实验的安全持续时间、硬件保护阈值和切除策略；
-   故障前稳态容差、温度容差和数据质量阈值；
-   根据仿真和预实验结果反推的测量精度要求。

**在上述参数确定之前，不应把某个电源、MCU 或 DAQ
型号写成最终采购结论。**

## 13. 核心结论

工况诊断器的核心不是让每次故障后的电气响应相同，而是保证每次反事实实验在故障位置之外具有一致、可追溯的物理条件，并准确记录故障建立、采集和切除的时间。

候选故障响应接近会影响 Method-A2
的故障位置辨识，但不应影响正常故障注入和计划切断时序。为避免两者耦合，实验控制应采用预设时序、实际开关反馈和同步
DAQ；独立硬件保护始终具有最高优先级。数据有效性诊断则在采集后综合工况、时序、保护和测量质量作出判断。
